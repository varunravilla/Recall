# P4: Recall code complete

[Live app](https://recall.mit-sdg.dev/) · [Final design document](docs/design-summary.md) · [Specifications](design/) · [Design notes](docs/design-decisions.md) · [Validation](docs/validation/README.md)

Recall preserves useful screenshots as undated finds or reviewed reminders.
Its source images remain available while the user searches, edits a reminder,
completes an intention, or deletes a saved item.

## Changes responding to feedback

- The former 509-line Recall composition now delegates to five workflow modules.
  Its specification explains each boundary, the ownership chain, successful-action
  consequences, optional read-model joins and refusal behavior.
- HTTP tests now exercise protected-route authentication and missing/foreign
  lookups, invalid inputs without writes, review/rejection, confirmation, due sweep,
  rescheduling, persistence, completion, dismissal, deletion and logout. Concurrency
  and legacy-date migration have explicit regressions.
- Required-field checks cover each ordinary endpoint individually. The production
  router, frontend network/session handling, upload result identities and terminal
  states have dedicated suites. [Coverage map](docs/testing.md) explains the risks
  and the tests that address them.
- The design summary explains concrete differences from P1 and P3. Earlier
  specifications are linked to exact commits rather than described as current code.

## Application journey

1. Create a password account and open Add photos.
2. Choose screenshots or an exported folder, allow analysis, then Find my saves.
3. Review a dated suggestion against its source image. Correct the action/time
   before Save reminder. Undated products and places appear in Saved as Found.
4. Search Saved, reload to check persistence, and open a saved detail URL.
5. Complete or dismiss an intention when finished. Delete a disposable saved item
   only after confirming its removal. Another account cannot read or alter it.

The [local browser observations](docs/validation/browser-p4.md) record a checked
review-to-completion path, direct-page persistence, missing-item recovery and phone
layout. The [browser checklist](docs/browser-checks.md) includes further access,
image-upload and accessibility cases.
The [deployed HTTP report](docs/validation/deployed-p4.json) records actual results
and their limits. It must be rerun after deploying the P4 fixes; a locally passing
suite does not establish that the deployed app runs the same code.

## Reproduce the checks

See the [README startup instructions](README.md#startup-guide), then run:

```sh
bun scripts/validate.ts
bun scripts/check-deployed.ts https://recall.mit-sdg.dev/
```

The second command creates two synthetic test accounts and deletes its own test
items. It sends no photos or AI requests and leaves existing accounts untouched.
The accounts remain because account deletion is not implemented. A nonzero exit
or a failed report entry means a check needs attention.
