# P4 recording outline

Record the deployed P4 version. Aim for 2–2½ minutes with narration throughout.
Use a future event screenshot and an undated restaurant or product screenshot.
Shorten an analysis wait with a labelled cut if needed. Do not imply a reminder
appeared unless it appears on screen.

| Show | Narration |
| --- | --- |
| Welcome and login | “Recall helps me return to screenshots when they become useful. It keeps the source image alongside a saved idea or reminder.” |
| Select two images and allow analysis | “I choose which photos to share for analysis. I can add more while an import runs, pause, or retry a failed photo.” |
| Dated suggestion, source image and an edit | “This concert has a time, so I review the suggestion against the image. I can correct the action and time before saving a reminder.” |
| Undated item in Saved | “This restaurant has no date. It stays as Found, without an invented deadline. Search helps me find it when I need a place to eat.” |
| Reload Saved and open its detail | “The images and saved details persist after reload. My account keeps them separate from other users’ collections.” |
| Due reminder if available, then completion | “Reminders appear in the open Inbox. After acting elsewhere, I mark an intention complete, which cancels its reminder.” |
| Delete a disposable item, then cancel or confirm visibly | “Deletion asks for confirmation and removes the image and its related records. I can also keep it and return later.” |
| Return to Saved | “The final design keeps undated ideas useful while making dated intentions explicit. Recall does not make purchases or bookings.” |

Use a separate account to demonstrate an empty collection if you want to illustrate
account isolation. A video is not a substitute for recording actual error and
access checks in the design notebook.
