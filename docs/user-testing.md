# Preparing Recall for user testing

Use test images and a participant-specific account. Explain that selected photos
leave the device for Google analysis, and allow the participant to decline.
Avoid private photos, real deadlines or valuable account credentials. Describe
these as tasks to attempt, not a tour of the correct controls.

## Tasks

1. You saved a concert announcement and want a reminder when tickets go on sale.
   Add it and check that the saved action and time reflect your intention.
2. You saved a restaurant screenshot without a date. Keep it so you can find it
   when deciding where to eat, then locate it again among several saved items.
3. Add another screenshot after an import finishes. Keep the earlier saved results.
4. You already acted on a reminder. Show that it no longer needs attention.
5. Remove a disposable saved item. Explain what you expect deletion to remove
   before confirming it.

## Observation guide

For each task, record whether the participant completes it independently, where
they hesitate, any recovery needed, and their own words about confusing labels.
Ask “What do you expect to happen?” before an uncertain action. Afterward, ask
“What would you change?” Avoid explaining the interface until the attempt ends.
Do not infer success from a screen change alone: check saved values and reload.

Check the phone layout, keyboard focus, 200% zoom, error messages and back
navigation before sessions. Keep a second account available for access-isolation
checks. Use a near-future reminder only if the participant understands it is test
data. No interviews or participant findings are claimed by this preparation file.
